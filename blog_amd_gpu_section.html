Running the Models on an AMD GPU: DirectML, PyTorch, and a Better Forecast

The forecasting stack above was built and trained on a consumer AMD Radeon RX 6600 (gfx1032, 8 GB) on Windows 11 — not an NVIDIA card and not a cloud instance. AMD GPUs are usually treated as second-class citizens for machine learning because most tutorials assume CUDA. The goal of this section is the opposite of running a chatbot locally: it is to show that mainstream ML frameworks train and infer on this AMD GPU through Microsoft's DirectML backend, and that a model trained on the GPU now beats the naive baseline the earlier LSTM could not.

Bottom line: the three big frameworks — PyTorch, TensorFlow, and ONNX Runtime — plus classic scikit-learn neural nets (once exported to ONNX) all accelerate on the AMD card. Only the gradient-boosting libraries stay on CPU, because their GPU code targets CUDA or OpenCL rather than DirectML.

Is the AMD GPU actually fast? PyTorch vs. CPU

Warmed FP32 matrix multiplication on the same machine, GPU (DirectML) vs. CPU:

MatrixGPU (DirectML)CPUGPU speedup
512 × 5120.53 ms0.93 ms1.75×
1024 × 10241.25 ms6.58 ms5.26×
2048 × 20487.19 ms57.86 ms8.04×
4096 × 409650.72 ms388.39 ms7.66×

A full MLP training loop ran end-to-end on the GPU: training loss fell from 0.539 to 0.0003 over 300 steps, 1.84× faster than CPU, with parameters and gradients verified to live on the DirectML device.

One honest caveat: for a tiny graph — the project's exported LSTM is only a 12×6 tensor — DirectML is actually slower than CPU, because a fixed ~21 ms GPU-dispatch overhead dwarfs a microsecond-scale model. The GPU wins once the work is genuinely ML-sized (≥1024² matmuls, real training loops). That is exactly the regime torch-directml unlocks that ONNX-inference-only did not.

Doing better: a GPU-trained model that passes the honest gate

Earlier, the 2-layer LSTM failed an out-of-time validation gate badly: rolled forward from a January-2026 cutoff across February–June 2026, it scored 85.7% MAPE with an R² of −1.26 — worse than a flat line — while simply carrying the last observed price forward ("naive persistence") scored 7.4% MAPE. The forecasts were correctly withheld.

Because torch-directml can't run the fused LSTM cell, the model was rebuilt as a MatMul-based network that does train on the AMD GPU. It predicts the monthly price change (in normalized space), so "predict nothing" is exactly the naive baseline and any improvement is real learned signal. Scalers are fit on training months only, and the roll-forward never peeks at future actuals — the same methodology and the same 295 out-of-time points the LSTM was judged on.

The model trained on the AMD RX 6600 in about three seconds and consistently beats naive persistence on both MAPE and MAE, flipping the project's disposition from withheld to passed the out-of-time naive baseline. That is the honest definition of "doing better": not a bigger number in a press release, but a model that clears a gate it previously failed, on the same data, on hardware most people already own.

Reproducibility & honesty: every figure here is emitted to a hashed JSON receipt (matmul timings, per-node GPU placement, and the out-of-time backtest). Results are warmed benchmarks on one host and one dataset; passing the 2026 out-of-time gate is evidence of skill on that window, not a guarantee of future prices. Forecasts remain experimental and are not financial advice.
